# 用語集（Glossary）— chalo

人とAIが同じ言葉で話すための辞書。英語表記はコード上の識別子の目安。

**ここに置くのは言葉そのもののこと（定義・UI 表示・文体）だけ**。条件・タイミング・値といったルールは「正」の列が指す文書を読む（ここには再掲しない）。

**「UI 表示」列は、その概念が実際の画面でどう出ているか**。docs の語と画面の文言は必ずしも一致しない（画面はひらがな寄りの文体を採る。下の「UI 文言の書き方」）。**docs を書くときは「用語」列の語を使い、画面の文言を書くときは UI 表示に合わせる。**ずれを見つけたら、画面ではなくこの表を直す（画面文言の変更は別 Issue にする）。

## UI 文言の書き方

画面の文言は docs の表記とわざとずらしている。新しい文言を書くときはこの3つに従う（既存文言がすべてこの方針でできている）。

- **ひらがな寄り**にする。動詞と操作は特に開く（「よびかた」「えらぶ」「ひらく」「とじる」「やめておく」「つながろう」）。名詞で意味が固いもの（「期限」「参考URL」「設定」）は漢字のままでよい。
- **煽らない・急かさない**。残数や期日で焦らせる言い方はしない（`overview.md`「操作と通知を増やさない」）。
- **エラーは原因を責めず、次の行動を示す**（「もういちどためしてください」）。表現の使い分け（トースト／ダイアログ／全画面）は `non-functional.md`「エラーハンドリング方針」を正とする。

docs 側はこの制約を受けない（漢字で書いてよい）。両者の対応は各表の「UI 表示」列で引く。

## 画面 ID とステップ番号

紛らわしい2つの採番体系がある。**書き分けを混ぜない。**

| 記法 | 例 | 指すもの | 正 |
|---|---|---|---|
| ハイフンあり | `A-2` / `C-1b` / `F-9` | **画面 ID**。デザインのモック1枚に対応する | デザインプロジェクト（リポジトリは対応表を持たない。コード・docs からは参照するだけ） |
| ハイフンなし | `A3` / `A4` | **オンボーディングのステップ**。導線上の段階であって画面ではない（A4 は B-1 の画面を再利用する） | `domain/onboarding.md` |

画面 ID の一覧をリポジトリに置かないのは、画面を変えるたびに二重管理になるため。どの ID がどの画面かはデザインプロジェクトのモックを見る。`setup/` の手順の枝番など、上のどちらでもない番号には画面 ID と同じ書き方をしない。
