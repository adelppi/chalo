# chalo ドキュメント

カップル向けの「行きたい所・やりたい事」を貯めて、いつか一緒に行くためのアプリ **chalo（チャロ）** の要求・要件・設計ドキュメント群。

`chalo` は「行こう！」の意。思いついたら手早く貯めて、二人でいつか行く。それが核となる。

## どこを読むか

| 知りたいこと | 文書 |
|---|---|
| 要求・コンセプト | `overview.md` |
| **何が実装済みで、何がまだ無いか** | `features.md` |
| 言葉の定義・概念と UI 表示の対応・UI 文言の文体を揃えたい（人もAIも） | `glossary.md` |
| ドメインのルール（状態・条件・タイミング） | `domain/` |
| データ構造の設計意図・RLS 方針 | `data-model.md`（列と型の正は `app/supabase/migrations/`） |
| 非機能・品質・公開要件 | `non-functional.md` |
| なぜその技術にしたか | `adr/` |
| 外部サービスの設定手順（Google/Apple サインイン等） | `setup/` |
| まだ決まっていないこと（決定バックログ） | `open-questions.md` |

ファイルの一覧は `ls docs/` / `ls docs/adr/` で見る（ここには再掲しない）。

## 書き分けのルール

同じ事実を複数の文書に書かない。各文書は次の関心ごとだけを持ち、それ以外はリンクで参照する。

| 層 | 問い | 文書 | 書くこと | 書かないこと |
|---|---|---|---|---|
| WHAT | 何を作るか | `features.md` | 機能の有無（実装済み／未実装／持たない） | 詳細ルール・ライブラリ・画面 |
| 振る舞い | どう動くか（業務ルール） | `domain/` | 状態・条件・タイミング等のルール | 技術的実現（ライブラリ／方式） |
| 実現 | どう作るか（技術判断） | `adr/` | 技術選定・実装方式とその理由 | — |

**一次情報は1か所だけ。** ある事実の「正」は1文書に置き、他文書は再掲せずリンクする。主な所在は次の通り。

| 事実 | 一次情報（正） |
|---|---|
| 実装済みか・未実装か・持たないか | `features.md` |
| ステータス定義・遷移／おしまい日／アルバム対象日 | `domain/plan-lifecycle.md` |
| 相手の名前の表示規則（呼び方の優先） | `domain/pairing.md` |
| 導線・入力項目・権限要求のタイミング | `domain/onboarding.md` |
| 通知の種類・条件・タイミング ／ 実装方式 | `domain/notifications.md` ／ `adr/0007` |
| オフライン挙動・権限拒否時の挙動・エラー網羅・対応範囲 | `non-functional.md` |
| テーブルの列・型・制約 | `app/supabase/migrations/`、`app/src/global/lib/supabase/database.types.ts` |
| データの設計意図（status 導出・退会時の付け替え）・RLS 方針・ON DELETE 方針 | `data-model.md` |
| 同期方式 ／ 編集ロック方式 | `adr/0004` ／ `adr/0005` |
| 未保存のフォームから離れるときの確認の実現方式 | `adr/0024` |
| ディレクトリ構成・レイヤ／依存ルール | `adr/0015` |
| データアクセス抽象化・状態管理 | `adr/0003` |
| ペア成立RPC・pair境界RLSの方針 | `adr/0017` |
| アカウント削除の実装方式（DB関数・Edge Function・Apple失効・消失検知） | `adr/0018` |
| UIスタイリング方針（NativeWind） | `adr/0016` |
| カレンダー ／ アルバムの実装方式 | `adr/0012` ／ `adr/0013`・`adr/0023` |
| 法的ページ（規約・ポリシー）のホスティング | `adr/0019` |
| マスコットの扱い（静的アセット・アニメーションを持たない） | `adr/0010` |
| ライブラリの実物・バージョン | `app/package.json`（選定理由は `adr/`） |

`glossary.md` は言葉そのもののこと（**定義・UI 表示・文体**）のみを置き、ルール（条件・タイミング）は上の正へリンクする。

## 未確定のことの書き方

記述にステータスの印は付けない。**印が無い記述は、現時点の決定**として読む。

未確定のものは本文に「〜は**未確定**（`open-questions.md` Q-〈領域〉-〈番号〉）」と書き、論点そのものは `open-questions.md` に Q-ID 付きで置く。本文とハブが必ず Q-ID で結ばれるため、どちらか一方に取り残されることがない。
