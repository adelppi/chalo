# ADR-0024: 未保存のフォームからの離脱は「戻るボタンに一本化」して確認する

- 関連: adr/0002, adr/0005, adr/0014, adr/0016, domain/plan-lifecycle.md, Issue #95

## コンテキスト

プランの作成（C-3）・編集（D-2）は同型のフル画面フォームで、保存するまで入力はローカルの state
にしか無い。画面から離れる経路は2つある。

1. ヘッダー左の戻る（`<`）。`global/utils/headerItems` の `unstable_headerLeftItems` で自前に描いており、
   押されたときの処理はアプリ側が持っている。
2. **画面左端からのスワイプ**（ネイティブスタックの戻るジェスチャー）。押下は OS 側で完結し、
   アプリはイベントを受け取っていない。

どちらも `router.back()` 相当で、未保存の変更は黙って消える（`Issue #95`）。

react-navigation の `usePreventRemove` は、この2経路をまとめて1か所で止められる。しかし
**expo-router が `usePreventRemove` を公開するのは SDK 58 から**である。SDK 57 の
`expo-router@57.0.22` は vendoring した react-navigation の中に実体を持つ
（`expo-router/build/react-navigation/core`）が、`expo-router` からは export していない。

## 決定

**確認ダイアログはフォーム画面が自前で出し、離脱経路を戻るボタン1つに絞る。**

- **戻るボタン**：`backHeaderOptions` に渡す `onBack` で、未保存の変更があれば `Dialog` を出す
  （変更が無ければそのまま `router.back()`）。
- **左端スワイプ**：未保存の変更があるあいだ `gestureEnabled: false` にして塞ぐ。確認を経ない
  出口を残さないため。変更が無いあいだは今までどおり効く。
- **内部パスからの `usePreventRemove` の import はしない**（`expo-router/build/...` は公開 API ではなく、
  SDK 更新で壊れうるため）。**SDK 58 に上げたら `usePreventRemove` に寄せ替える**。そのときスワイプも
  確認の対象にできるので `gestureEnabled` の出し入れは不要になる。
- **判定は純粋関数**：入力値の整形（前後空白・日付なしの時刻・日付ありの期限）と変更の有無を
  `plans/model/draft.ts` に切り出し、Jest でテストする（`adr/0014`）。保存時に組み立てる値と
  同じ整形を通してから比べる（空白を足しただけを「変更」と読まないため）。
- **`Dialog` に `onDismiss` を足す**：既存の `Dialog` は背景タップ＝`onCancel` だった。この確認では
  キャンセル側が「保存せず戻る」＝後戻りできない選択になるため、**背景タップでは何もしない**
  （編集に戻る）ように、押さずに閉じただけを分けられる口を用意する。省略時は従来どおり `onCancel`。

ダイアログの中身（2ボタン・文言）は `domain/plan-lifecycle.md`「作成・編集の中断」を正とする。

## 結果

- 良い点
  - 公開 API だけで実現でき、SDK 更新で壊れる内部依存を持たない。
  - 「確認が出ない出口」が無い。戻る以外で画面を離れられないため、経路ごとの挙動差が生まれない。
  - 整形と変更判定が1か所（`model/draft.ts`）に集まり、保存時の値と確認の判定が必ず一致する。
- 留意点
  - **未保存のあいだ、左端スワイプが効かない**。iOS の一般的な操作感からは外れる（SDK 58 で解消予定）。
  - 変更判定はフォームの値だけを見る。相手が同じプランを編集していた場合の競合は編集ロックの担当
    （`adr/0005`）で、この確認では扱わない。
  - `Dialog` の `onDismiss` は他の呼び出し元の挙動を変えない（省略時は `onCancel`）。

## 検討した代替案

- **内部パスから `usePreventRemove` を import する**：2経路を1か所で止められて理想形に近いが、
  `expo-router/build/react-navigation/core` は公開 API ではない。SDK 58 で正式公開されると分かっている
  ものを、数か月のために内部依存として抱えるのは割に合わない。
- **スワイプは今までどおり黙って破棄する**：実装は小さいが、同じ「戻る」なのに経路で結果が変わる。
  データが消える側の不一致なので採らない。
- **`Alert.alert`（OS 標準アラート）で聞く**：実装は最小だが、確認は `Dialog`（F-1 系）で出すのが
  アプリ全体の作法（削除・書き出し等）。見た目が1か所だけ OS 標準になるため採らない。
- **自動下書き保存**：戻っても失われないので確認自体が要らなくなるが、「保存する」を押すまで相手に
  見せないという作成・編集の前提を変える。範囲が大きく、この Issue では扱わない。
